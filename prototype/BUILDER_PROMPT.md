# 다음 제작 단계용 프롬프트

현재 파일은 v0.2 화면·흐름 수정본이다. 실제 브라우저 실행이 차단되어 시각 검토가 끝나지 않았다. `QA_NOTES.md`의 PC·모바일 검토를 먼저 마친 뒤 연결 단계로 진행한다. 코드 검사를 시각 검토 완료로 간주하지 않는다.

아래 내용을 `index.html`, `IMPLEMENTATION_BRIEF.md`, `MENTOR_SYSTEM_PROMPT.md`와 함께 전달한다. 화면 확인만 하는 단계라면 아래의 서버 연결 작업을 임의로 완료했다고 표시하지 않는다.

---

첨부한 **선물(선배에게 물어봐)** 시제품을 기준으로 실제 서비스 연결을 진행해줘.

## 먼저 확인할 것

첨부 코드와 명세를 읽고 현재 구현과 미구현을 구분해줘. 이 시제품은 단일 HTML과 브라우저 로컬 저장을 사용하며, 채팅은 준비된 예시 응답이다. 실제 AI·회원 인증·서버 DB·실제 선배 전송·외부 알림은 연결되지 않았다.

먼저 기존 화면을 실행해 확인하고, 구현된 기능을 같은 기능으로 다시 만들기만 하지 말아줘. 백엔드 공급자와 배포환경은 현재 프로젝트의 실제 설정을 확인한 뒤 사용해줘. API 키가 없으면 화면에 입력을 요구하거나 코드에 하드코딩하지 말고 서버 환경변수 자리와 연결 상태를 분명히 남겨줘.

## 변경하면 안 되는 제품 결정

- 이름: 선물(선배에게 물어봐)
- 슬로건: 후배가 선배가 되는 날까지
- 핵심: 신입이 눈치 보지 않고 물어볼 수 있는 편한 선배
- 홈 인사: 고정하지 않고 재접속·홈 재진입 시 몇 가지 중 변경. 입력 중에는 고정
- 카테고리: 실무가 헷갈려 / 거래처 때문에 난감해 / 사수한테 묻기 애매해 / 그냥 고민 좀 들어줘
- 닉네임을 자연스럽게 사용하는 대화
- 새싹·나무 그림은 닉네임 카드에만 작게 유지
- 그 외 화면이나 답변에는 나무 세계관·물주기·레벨·랭킹을 넣지 않기
- 제공 횟수·유료서비스는 나중에 결정. 현재 제한과 결제는 OFF
- 실제 선배 상담을 AI가 임의로 접수하지 않기
- 질문 수나 말투만으로 능력·정확성·멘토 자격을 평가하지 않기

## 연결할 핵심 흐름

1. 닉네임과 별개인 계정 인증 및 사용자 ID
2. 사용자별 대화·메시지 서버 저장
3. 승인·검수된 지식만 검색하는 실제 AI 답변
4. 답변 근거 부족 시 상담 제안
5. 사용자가 전달할 요약과 메시지를 확인하고 동의
6. 상담 접수와 운영자 알림
7. 멘토 답변 등록과 사용자 알림
8. 자기기록과 실제 멘토 피드백 중심 성장기록
9. 상담 답변의 비식별화·동의 확인·검토 전 노하우 초안 생성
10. 운영자 승인 후에만 노하우를 AI 검색 대상에 포함

## 보안과 상태

실제 서비스에서는 운영자 화면 시연 버튼을 누구나 쓸 수 있게 두면 안 돼. 서버에서 사용자·멘토·운영자 권한을 검증하고, 멘토는 배정된 상담과 공유에 동의한 내용만 볼 수 있게 해줘.

API 키·DB 관리자 키·알림 발송 키를 HTML 또는 프런트엔드 코드에 넣지 마. 외부 알림에는 민감한 질문 전문 대신 접수/답변 도착 사실과 인증된 링크를 사용해줘.

상담 저장 성공과 알림 발송 성공은 별도 상태로 처리하고, 실패·재시도·중복 방지를 구현해줘. 모델 호출 실패를 정상 답변으로 저장하지 마. 사용자가 작성한 메시지는 장애 중에도 잃지 않도록 해줘.

상담 공유 동의와 노하우 재사용 동의를 별도로 관리해줘. ‘저장’ 버튼을 눌렀다고 AI가 자동으로 재학습하는 것처럼 설명하면 안 돼.

## 결과물

설명으로만 마무리하지 말고 실제 수정 코드, 데이터 구조/마이그레이션, 필요한 환경변수 이름, 로컬 실행방법, 테스트 결과를 제공해줘. 아직 연결되지 않은 부분과 사용자가 직접 준비해야 하는 계정·키·권한을 정확히 구분해줘.

인증·권한과 서버 저장부터 작은 단위로 구현하고 테스트한 뒤 AI와 알림을 연결해줘. 첨부 시제품의 화면과 말투는 유지하되, 접근성·오류 처리·모바일 입력 사용성 문제는 개선해줘.
