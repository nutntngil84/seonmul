# 검증 범위 · v0.3

## 실제 수행

- v0.2.1 `README.md`, `IMPLEMENTATION_BRIEF.md`, `index.html`을 읽고 기존 코드와 원본 ZIP이 일치함을 확인했다.
- 기존 시제품 8개 파일을 `prototype/`에 그대로 보존했다.
- 새 UI를 번들링한 독립 HTML을 실제 Chromium headless 브라우저로 실행했다.
- 1280×900, 390×844, 320×844 크기에서 홈을 렌더링하고 전체 가로 넘침을 검사했다.
- 화면 캡처를 직접 확인하고 320px 질문 버튼의 글자 잘림, 채팅 즐겨찾기 버튼의 위치 문제를 수정했다.
- 브라우저에서 접수 공유 확인·내용 수정 시 재동의·재사용 기본 OFF·선배 직접 답변·후배 알림·즐겨찾기·배운 점·피드백·동의 철회·새로고침 후 로컬 기록 유지를 확인했다.
- 저장 실패를 주입해 입력과 확인 화면이 유지되고, 재시도 후 한 번만 저장되는지 확인했다.
- 원격 API 대신 로컬 PostgreSQL 엔진 PGlite에 실제 SQL을 적용해 권한·RPC·알림 트랜잭션을 테스트했다.
- Android·iOS 프로젝트를 실제 생성했으며 Capacitor push plugin 연결 파일을 확인했다.

## 프로필 소개글 추가 검증

- Chromium에서 선택 입력, 100자 제한과 글자 수 표시, 저장·새로고침 유지, 빈 값으로 지우기를 확인했다.
- 320px 화면에서 100자 소개글이 가로로 넘치지 않으며, HTML 태그 입력은 일반 글자로 표시되는지 확인했다.
- 모바일 입력 화면과 모바일·PC 프로필 카드 캡처는 `screenshots/06-profile-bio-edit-mobile.png`, `07-profile-bio-mobile.png`, `08-profile-bio-desktop.png`에 저장했다.
- PGlite에서 기존 프로필에 빈 소개글을 추가하는 마이그레이션, 본인 소개글 수정, 101자 저장 거부를 확인했다. 원격 서버 저장은 아직 검증하지 않았다.
- 시연·웹 빌드와 Capacitor 동기화를 완료했다. 아래 기존 자동화 사례 수에는 이 추가 수동·임시 스크립트 검증을 포함하지 않는다.

## 테스트 파일

### 역할별 화면 구분 · 2026-09-24

- 후배 홈의 질문 입력·카테고리와 선배 홈의 받은 질문 동선을 분리했다. 선배 메뉴에는 받은 질문·알림·상담 노하우를 표시한다.
- 실제 Chromium에서 1280·390·320px로 역할별 홈, 받은 질문 목록, 질문 검토창, 상담 대화의 가로 넘침을 검사했다.
- `보낼 내용 확인`만 누르면 접수되지 않고 공유 동의 후 접수되는지, 선배가 받은 질문을 열어 직접 답변하고 후배가 알림에서 읽는지 확인했다.
- 선배의 `답변 완료`와 후배의 `답변 도착` 표시, 역할별 인사 변화, 소개글 유지, 경력 변경으로 역할이 바뀌지 않는 동작을 확인했다. 브라우저 실행 오류는 없었다.
- 화면 캡처는 `screenshots/09-role-junior-desktop.png`부터 `13-role-received-mobile.png`까지다. 시연·운영용 웹 빌드와 Capacitor 동기화를 완료했다.
- 위 확인은 별도 임시 스크립트로 수행했다. 아래 기존 자동화 사례 수와 원격 서버·실기기 검증 범위는 그대로다.

### 기존 자동화 파일

- `tests/database.test.mjs`: 11개 사례. 본인/배정 권한, 타인 차단, 역할 사칭 및 회수, 메시지 직접 쓰기 금지, 공유 동의, 요청 재시도, 질문·답변 알림, 재사용 검수/철회, 개인 기록, worker 권한/재시도, 기기 계정 변경, 선배 없음, 계정 삭제 cascade.
- `tests/browser.mjs`: UI 시나리오 9개. 결과는 `UI_TEST_RESULT.json`, 화면은 `screenshots/`.
- `scripts/release-check.mjs`: 공개 서버 설정·정식 앱 ID·개인정보/연락처·체험 OFF·공개 키 검사. 설정 없는 등록 빌드는 중단한다.

## 수행하지 않은 검사

- 실제 Supabase 프로젝트의 이메일 가입·확인·로그인·RLS·서버 영속 저장·다른 기기 동기화.
- Edge Function을 실제 Deno/Supabase 환경에서 배포·호출하는 검사.
- FCM/APNs의 실제 발송·재시도·token 갱신·로그아웃 및 계정 전환 실기기 검사.
- Android/iOS 실기기의 터치 키보드·백그라운드·cold start push 이동·접근성 및 OS별 렌더링.
- Android Gradle 릴리스 빌드, Xcode Archive, 코드 서명, AAB/IPA 생성, 스토어 심사.
- 실제 보관/삭제 운영 정책, 메일 복구 흐름, 신고·차단 및 운영 프로세스.

따라서 로컬 검증을 정식 서버·휴대폰 푸시 연결 완료 또는 앱 등록 완료로 해석하지 않는다. `docs/DEPLOYMENT.md`의 실환경 검증을 마친 뒤 출시한다.
