# 선물 · 실제 선배 상담 앱 v0.3

**후배가 선배가 되는 날까지.**

첫 출시 방향을 실제 선배 상담으로 변경했습니다. 지식베이스 없이 시작하며, 후배의 질문에 선배가 직접 답합니다. 상담 기록이 서버에 쌓이고, 별도 재사용 동의를 받은 답변만 노하우 검토 후보가 됩니다. AI 자동 답변·자동 학습·결제·제공 횟수 제한은 없습니다.

기존 `README.md`, `IMPLEMENTATION_BRIEF.md`, v0.2.1 코드를 먼저 확인했습니다. 기존 색상·CSS·아이콘·홈 인사·닉네임 카드의 경력 그림을 재사용했고, 즐겨찾기와 성장기록을 이어갔습니다. 이전 원본 8개 파일은 `prototype/`에 그대로 보존했습니다. 현재 개발 기준은 이 README와 루트의 `IMPLEMENTATION_BRIEF.md`입니다.

## 지금 확인하는 방법

`seonmul_v0.3_preview.html`을 브라우저에서 열면 설치 없이 둘러볼 수 있습니다. 이 파일은 **로컬 체험 전용**입니다. 실제 개인정보나 업무자료를 입력하지 마세요.

1. **후배로 둘러보기** → 닉네임 카드에서 경력을 바꾸고 **소개글(선택, 최대 100자)**을 적습니다. 소개글은 홈과 설정의 내 프로필 카드에 표시됩니다. 비우고 저장하면 삭제됩니다.
2. 후배 홈에서 질문 → **보낼 내용 확인** → 상담 공유에 동의 → 체험 접수. 확인 버튼만으로 접수되지 않습니다.
3. 설정 → **선배 답변 화면** → 선배 홈의 **받은 질문 보기** → 접수한 상담 → 직접 답변·피드백 입력.
4. 설정 → **후배 화면** → 알림 → 답변 확인 → 배운 점 남기기.
5. 성장기록과 내 대화의 즐겨찾기를 확인합니다.
6. 재사용을 선택한 상담은 선배 설정의 **상담에서 쌓인 노하우**에 후보로 모입니다. 운영자 역할에서 비식별 질문·답변을 직접 정리합니다. 후배가 동의를 철회하면 해당 후보와 검수본을 삭제합니다.

앱은 비동기 상담입니다. 답변 시간은 보장하지 않습니다. 단순 인사 문구와 안내 외에는 선배가 입력하기 전 답변이 생기지 않습니다.

홈과 주요 메뉴는 역할별로 구분합니다. 후배는 질문 입력·카테고리·내 대화·선배 상담·성장기록을 이용합니다. 선배는 질문 입력란 없이 받은 질문·알림·상담 노하우를 확인하고, 배정된 상담 안에서 답변을 등록합니다. 선배에게는 답변 상태를 **답변 완료**, 후배에게는 **답변 도착**으로 표시합니다. 경력 선택과 실제 선배 권한은 별개입니다.

## 연결 상태

| 영역 | 이번 결과 | 실제 서비스 검증 |
|---|---|---|
| 화면 | 기존 디자인을 이어 직접 상담 흐름 구현 | Chromium에서 PC·모바일 폭 실행 확인 |
| 계정 | Supabase 이메일 가입·로그인 코드 | 프로젝트·메일 설정 미연결 |
| 권한 | DB 권한 분리, 후배 본인·배정 선배만 상담 열람 | 로컬 PostgreSQL 엔진 테스트 통과; 원격 RLS 검증 필요 |
| 서버 저장 | 상담·메시지·동의·피드백·배운 점·즐겨찾기·알림 SQL 및 API | 실제 서버 미배포 |
| 알림함 | 질문→선배, 답변→후배 알림을 DB 트랜잭션에 포함 | 로컬 흐름·SQL 테스트 통과 |
| 휴대폰 푸시 | Android FCM·iOS APNs 등록 및 전송 worker 코드 | 인증 정보·정기 실행·실기기 미연결 |
| 앱 프로젝트 | Android·iOS Capacitor 네이티브 프로젝트 생성 | APK/AAB/IPA 미빌드, 서명·등록 안 함 |
| AI | 사용하지 않음 | 연결·학습 안 함 |

**이 패키지는 서버와 앱 등록을 준비하는 개발본입니다. 정식 출시 완료본이 아닙니다.**

## 개발 실행

Node.js 22 이상을 사용합니다. 잠금 파일이 포함되어 있습니다.

```sh
npm ci
npm run dev
```

서버 설정이 없고 개발 모드이면 명시적으로 둘러보기를 선택할 수 있습니다. 네트워크 인터페이스 조회가 제한된 환경에서는 `npx vite --host 127.0.0.1`을 사용합니다.

```sh
npm test                 # 로컬 PostgreSQL 권한·상담·알림 테스트
npm run build:demo       # 독립 HTML 체험 파일 생성
npm run test:ui          # Chromium으로 화면·흐름 검증
npm run build           # 연결 미설정이면 접수 불가 화면으로 빌드
npm run build:release   # 필수 설정·앱 ID·체험 OFF 검사 후 운영 빌드
```

UI 테스트는 로컬 HTML을 실제 브라우저에서 실행합니다. 실서비스의 인증·네트워크·푸시 성공을 입증하지는 않습니다. 검증 범위는 `docs/QA_NOTES.md`를 참고하세요.

## 다음 연결에 필요한 것

제니 명의의 Supabase 프로젝트, Firebase 프로젝트, Google Play 개발자 계정과 Android 서명이 필요합니다. iOS 등록에는 Apple Developer 계정과 Mac/Xcode, APNs 키가 추가로 필요합니다. 비밀키를 대화에 붙여 넣거나 앱의 `VITE_` 변수에 넣지 않습니다.

앱 ID·운영 연락처·개인정보 처리방침·삭제 요청 웹페이지·실제 선배 계정을 확정한 뒤 `docs/DEPLOYMENT.md` 순서대로 연결합니다. 먼저 두 실제 계정·두 기기로 질문 및 답변 알림을 확인한 후 스토어 테스트에 올립니다.

## 파일 구성

- `src/`: 기존 디자인 요소, 실제 API adapter, 체험 adapter, 상담 UI, 네이티브 푸시 등록
- `supabase/migrations/`: 권한·DB·질문/답변 RPC·알림 대기열
- `supabase/functions/`: 푸시 전송과 본인 계정 삭제
- `android/`, `ios/`: 생성된 네이티브 프로젝트. 고유 앱 ID·서명·provider 설정 필요
- `docs/DEPLOYMENT.md`: 실제 서버·푸시·앱 등록 순서
- `docs/QA_NOTES.md`, `docs/screenshots/`: 수행한 검사와 남은 출시 검증
- `prototype/`: 변경 전 v0.2.1 원본. 새 배포에 포함하지 않음

기존 로컬 시제품 기록이나 정리한 엑셀 73개 답변은 실제 사용자 서버에 자동 업로드하지 않습니다. 이번 구조는 지식베이스를 준비하지 않아도 운영을 시작하도록 설계했습니다.
